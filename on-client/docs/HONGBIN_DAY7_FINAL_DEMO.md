## 2. 핵심 기능 세 가지 시연 순서 (권장 3~5분)

사전 준비: Windows PC에서 프로젝트의 `on-client` PowerShell을 열고 로컬 앱 실행. 기본 화면을 보여 주고 **실제 측정은 버튼을 누를 때만 진행**한다. 화면의 샘플/예제 자료를 실제 값이라고 말하지 않는다.

### 1) 기록 보기 — Windows 이벤트와 XDR을 구분 (약 1분)

1. **보호 현황** 아래쪽 **「연결·설정·기록 조회」** 버튼을 누른다. 조회 중 메시지가 바뀌는지 보고 결과를 확인한다.
2. 네트워크 링크 연결, 방화벽 프로필, **System·Application 최근 24시간 경고/오류 건수**와 **각 조회 시각**을 보여 준다. 값을 못 읽으면 항목별로 **확인 불가와 사유**를 설명한다.
3. 왼쪽 **「보안 기록」**으로 이동한다. 기존 XDR은 외부 SDP가 미연결이므로 실제 XDR 이벤트를 조회할 수 없다고 설명한다.
4. 말할 내용: **‘Windows 이벤트 경고·오류 수는 일반 OS 기록이며, 공격·침해 탐지 건수가 아닙니다.’**

### 2) 내 PC 상태 — 4개 실측 카드와 비교 (약 1분)

1. **보호 현황**으로 돌아와 맨 위 **「내 PC 상태 측정」** 버튼을 누른다.
2. CPU(%), 메모리(% 및 GiB), 디스크 여유 공간(GiB), **마지막 측정 시각** 카드 네 개를 확인한다. C:/D: 디스크를 각각 구분한다.
3. 다시 버튼을 한 번 누른 뒤 아래 **이전 측정 대비 변화**를 보여 준다. 첫 조회에는 비교할 이전 값이 없어 정상적으로 비교를 표시하지 않는다.
4. 말할 내용: **‘실제 Windows 일반 권한 조회값이며, 예시 숫자가 아닙니다. 새로고침하면 이전 비교 기록은 초기화됩니다.’**

### 3) 위험 알림 — 연결/조회 실패와 실제 탐지를 혼동하지 않기 (약 1분)

1. **보호 현황 → 학생 상태·알림 표시** 영역의 **핵심 기능 3가지** 안내와 빨간 **조회 실패** 영역을 보여 준다.
2. 현재 **ENGINE_NOT_CONNECTED / SDP 미연결**을 가리키며 외부 보안 원천 데이터 미연결이라는 점을 설명한다. 로컬 PC 조회 성공과 별개임을 강조한다.
3. 실패한 항목, 오류 코드, **다음 행동**(해당 버튼 직접 다시 조회)을 확인한다. 보안 기능의 실제 차단·집행은 시연하지 않는다.
4. 말할 내용: **‘위험 알림의 실제 자동 탐지·통보는 미구현/미검증입니다. 지금 보이는 것은 주로 연결·조회 오류 안내입니다.’**

**7일차 시연 관측 (2026-11-03 15:36~15:38):** 사용자가 기록 조회 → PC 실측 → 상태·오류 화면의 캡처 5장을 공유했다. 세 핵심 화면의 실제 표시 및 시각·오류 안내를 확인했으며 아래 근거 표에 기록했다. 이후 **15:48경 두 번째 PC 측정 화면**이 추가되어 이전 시각 대비 CPU·메모리·디스크 변화 표시까지 실제로 확인했다. 단, **조회 중 대기 표시와 키보드 단독 조작은 사용자 화면에서 아직 검증되지 않았다.** 확인되지 않은 것은 성공으로 쓰지 않는다.

## 4. 남은 한계 및 ‘확인 불가’ 목록

- **외부 SDP:** 기본 실행에서 미연결. 외부 원천 데이터가 실제로 연결되었다는 증거가 없음. 연결 실패를 PC 측정 실패로 오인하지 않는다.
- **XDR 위험/자동 위험 알림:** 기존 UI와 오류 안내는 있지만, 실시간 공격 탐지·차단·위험 알림 발송 기능이 완성·검증된 것은 아니다.
- **AI·조치:** 실제 AI 사건 설명, 사람 승인 후 원천 서버 조치의 최종 효과 관측은 확인하지 못했다. 실제 조치 버튼으로 위험한 테스트를 하지 않는다.
- **이벤트 범위:** System·Application 최근 24시간 Level 2(Error), 3(Warning)의 건수 요약. Security 로그 및 침해 판단을 포함하지 않으며, 접근 권한·시간 초과 시 확인 불가로 남긴다.
- **네트워크/방화벽:** 링크 Up은 인터넷 접속을 보증하지 않고, 방화벽 활성화만으로 안전을 보증하지 않는다. 읽기 전용이며 설정 변경은 하지 않는다.
- **저장/그래프:** 이전 측정은 브라우저 탭에서만 유지한다. 페이지 새로고침 후에도 남는 지속형 데이터베이스/저장형 추이 그래프는 미구현.
- **재현 범위:** 같은 PC의 별도 폴더는 확인했다. 다른 사용자 계정/다른 PC/외부 사용자 단독 실행은 미검증.
- **대기·키보드:** 7일차 화면에서 기록·실측·연결 오류 안내 및 **같은 브라우저 탭에서 두 번째 PC 측정 후 변화 표시**는 확인했다. 그러나 조회 중 대기 표시와 키보드만으로 조작하는 실사용 시연은 아직 검증하지 않았다.
- **공식 제출:** 과거 22단계 ‘마무리 자료 제출’은 **승인되었다**는 포털 화면을 확인했다. 7일차 추가 문서가 그 승인본에 자동 반영되거나 새로 승인되었다고 주장하지 않는다.

## 5. 실행 명령과 최종 확인 순서

실행 위치: 기존 프로젝트 또는 **별도 테스트 폴더의 `on-client`**. 파일 탐색기에서 `on-client`를 열어 주소창에 `powershell`을 입력하고 Enter를 누른다.

```powershell
git branch --show-current
git status --short
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Port 5191
```

Node.js 22~24(기준 24.19.0, 검증된 실제 PC 24.22.0), 설치/포장 명령 불필요. `-Port 5191`이 사용 중이면 스크립트 안내에 따라 다른 비어 있는 포트를 쓴다. **브라우저 주소창에 직접** `http://127.0.0.1:5191/`을 입력한다. 주소 뒤에 `?utm_source=...`나 `**`가 붙으면 `QUERY_REJECTED`가 발생할 수 있다.

브라우저 보호 현황에서 **「연결·설정·기록 조회」 → 「내 PC 상태 측정」(2회) → 「학생 상태·알림 표시」** 순서로 시연한다. 반드시 각 측정 **단위·시각**을 함께 설명한다. 연결 없는 XDR은 ‘확인 불가’라고 말한다.

종료는 서버를 실행한 PowerShell 창에서 `Ctrl+C`. 서버가 5190 등 다른 포트에서 이미 실행 중이어도 다른 프로세스를 강제로 종료하지 않는다.

**7일차 개발 커밋을 로컬 폴더에서 확인할 때**는 서버 종료 후 (기존 작업 변경이 없는 경우에만) 다음을 실행한다.

```powershell
git fetch origin
git switch --track -c feature/day7-final-demo origin/feature/day7-final-demo
git rev-parse HEAD
```

이미 동일 이름의 로컬 브랜치가 있다면 `git switch feature/day7-final-demo`로 전환한다. **강제 push, reset --hard, 기존 커밋 덮어쓰기 금지.** 최신 40자리 SHA는 실제 `git rev-parse HEAD`와 GitHub의 `feature/day7-final-demo` 브랜치가 일치하는 것으로 확인한다.
